## Notes

- **Urutan dependensi**: M0 (tipe + kontrak) → M1/M2 (currency + fee) → M3 (wallet) → M4 (COD hold) → M5 (delivery + OTP) → M6 (dispute) → M7 (pajak) → M8 (push) → M9 (ledger) → M10 (insentif merchant) → M11 (verifikasi lintas role).
- **Status per 2026-09-23**: **M0–M11 `done`** — tipe/konstanta/walletSlice, tampilan IDR+JOD, fee checkout + gate saldo, wallet & top-up/payout, hold COD, checkpoint pengiriman + OTP, sengketa, pajak info-only, nomor WA + push mock, ledger & liability, insentif merchant, dan verifikasi lintas role. Sisa pekerjaan ada di bagian "Item di luar milestone" di bawah.
- **Repo ini mock-only**: seluruh kolom kontrak BE menjelaskan API masa depan. Tidak ada backend, pembayaran, atau auth sungguhan (AGENTS.md §1).
- **Panel admin (CS) vs Super Admin**: konsol `/admin` adalah panel admin platform yang dikelola **CS** (keputusan PO 2026-09-23); shell 430px dipertahankan karena CS memakainya dari ponsel. **Super Admin role terpisah** — kelak website penuh non-PWA (prefix `/superadmin`), cakupan `UNRESOLVED` (lihat `decision-irbid-mvp.md`). Berlaku untuk M6 dan M9: aktornya panel CS, bukan Super Admin.
- **Referensi UI/UX**: repo 4 portal `baihaqybeki/sa7tein` (customer, merchant, courier, CS) dipakai sebagai acuan layar/alur saja — bukan target implementasi. Ringkasan ada di `repo-sa7tein-schema.md`. Portal CS-nya bisa jadi acuan bentuk Super Admin, tapi nama & shell mengikuti keputusan repo ini.
- **Design system di luar cakupan** dokumen ini (diputuskan PO 2026-09-21).

## Item di luar milestone (terbuka)

- **Model ongkir — SELESAI (2026-09-23).** PRD v2 memutuskan zona **Hijazi/Syimali ≤2 km** + merchant mengaktifkan zona (`C-13`), ongkir **100% merchant** (`C-07`) lewat `merchantDeliveryConfig`. Kode sudah dimigrasikan dari pita radius A/B/C (legacy) ke model ini; dokumentasi di `/documentation` bagian 32. **Nominal ongkir final tetap `UNRESOLVED`** (flow `f20-address-zone`), jadi angka di kode adalah placeholder — bukan tarif aktif.
- **Cakupan Super Admin — SELESAI (2026-09-23).** Website penuh non-PWA, prefix `/superadmin`: master zona Hijazi/Syimali, manajemen role & permission penuh, audit trail, laporan pajak aplikasi, saldo keuntungan platform (net profit, satu-satunya dana yang bisa di-withdraw SA), kill switch/mode maintenance, monitoring ledger detail, dan **registri pengguna** (`/superadmin/users` — customer, merchant, kurir, dengan **dossier per merchant** di `/superadmin/users/merchant/:id`). Top-up/payout customer & merchant = self-service sistem, bukan approval SA. Panel CS menjalankan approval tenant, putusan sengketa level-1, dan blacklist COD; SA mengaudit, menangani banding, dan **sejak revisi 2026-09-23 boleh suspend/aktifkan kembali status tenant** dari dossier (izin `tenant.status`, tercatat atas nama operator SA). **Registri pengguna ditambahkan 2026-09-23** setelah audit menemukan tidak ada pendataan pengguna sama sekali: rujukan antar-modul dipindah dari nama ke id, `LedgerEntry` dapat `party`, audit dapat `actorId`, dan daftar kurir lintas merchant diizinkan untuk pengawasan (**menyimpang** dari `source.md:296` — kewajiban kurir tetap milik merchant). Rincian + `UNRESOLVED` (OQ-30, jadwal settlement, taksonomi target audit) di `decision-irbid-mvp.md`.
- **Panel CS menampilkan IDR + JOD — SELESAI (2026-09-23).** `R-CURR-01` menetapkan IDR source of truth dan JOD display-only, jadi konsol CS tidak boleh JOD-only. Layar uang panel CS (Ringkasan, Ledger, Sengketa, Merchant, Onboarding) kini memakai `moneyFromJod()` + widget disclaimer; dokumentasi di `/documentation` bagian 22.
